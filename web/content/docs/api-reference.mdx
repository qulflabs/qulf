# Qulf API Reference

The `Qulf` class is the central orchestrator of the authentication engine. Below is a comprehensive reference of its public methods and internal behaviors.

## Initialization & Extensibility

### Schema Injection
When you instantiate the `Qulf` engine with a list of plugins, it performs an architecture technique known as **Schema Injection**. 

1. During `__init__`, Qulf iterates over all provided plugins and calls their `get_custom_columns()` hook.
2. It aggregates these columns (e.g., `github_id` from the OAuth plugin).
3. It passes this aggregated schema to the underlying Database Adapter via `inject_custom_columns()`.
4. The database adapter dynamically updates its ORM models (like SQLAlchemy tables) to include these new columns before the application fully boots.

This ensures you never have to manually write database migrations when installing an official Qulf plugin!

### `get_plugin(plugin_class: type[TPlugin], name: str | None = None) -> TPlugin | None`
Safely retrieves a registered plugin by its class type. This returns a properly typed instance so your IDE retains autocomplete!

If you have multiple instances of the same plugin class installed, you can pass an optional `name` parameter to target a specific instance.

```python title="app/routes.py"
from qulf.plugins.oauth import OAuthPlugin

# Retrieves the first mounted instance of OAuthPlugin
oauth_plugin = auth.get_plugin(OAuthPlugin)

if oauth_plugin:
    print(oauth_plugin.providers)
```

## Authentication Methods

### `sign_up(user_data: UserCreate) -> User`
Registers a new user in the database.
*   **Hooks Executed:** `before_user_create`, `after_user_create`
*   **Exceptions:** Raises `UserAlreadyExistsError` if the email is taken.

### `sign_in(email, password, ip_address=None, user_agent=None) -> Session`
Validates credentials and generates a new session.

**Scenario 1: Standard Login**
```python
session = await auth.sign_in("user@example.com", "mypassword")
```

**Scenario 2: Secure Login with Context Tracking**
You can optionally pass network information so plugins (like Audit Logging or Rate Limiting) can track the context of the login.
```python
session = await auth.sign_in(
    email="user@example.com", 
    password="mypassword",
    ip_address=request.client.host,
    user_agent=request.headers.get("user-agent")
)
```

### `sign_out(token: str)`
Destroys a session token by deleting it from the database (if using the database session strategy).

## Session Management

### `create_session(user: User, ip_address, user_agent) -> Session`
Generates a new session based on the configured strategy (Database or JWT).

### `validate_session(token: str) -> tuple[Session, User] | None`
Verifies a session token. Returns a tuple of the session and user if valid, or `None` if the token is expired or invalid.

**Scenario 1: Middleware Validation**
Most frameworks use this under the hood to validate incoming API requests.

**Scenario 2: WebSocket Authentication**
You can use this method to securely authenticate persistent connections where cookies might not be easily accessible.
```python
async def websocket_endpoint(websocket: WebSocket, token: str):
    result = await auth.validate_session(token)
    if not result:
        await websocket.close(code=1008) # Policy Violation
        return
        
    session, user = result
    await websocket.accept()
    # Proceed with authenticated websocket...
```

### `get_session_from_cookies(cookies: dict) -> tuple[Session, User] | None`
A helper method that extracts the token using the configured cookie name (`QULF_SESSION` by default) and passes it to `validate_session`. 

```python title="app/routes.py"
# FastAPI Example
result = await auth.get_session_from_cookies(request.cookies)
```

### `get_user_sessions(user_id) -> list[Session]`
Returns all currently active sessions for a specific user.

### `revoke_session(user_id, token) -> bool`
Deletes a specific session. Useful for a "Sign out of this device" feature.

### `revoke_all_user_sessions(user_id, except_token=None) -> list[str]`
Deletes all sessions for a user.

**Scenario 1: Total Compromise**
If a user reports their account was hacked, sign them out of everywhere.
```python
await auth.revoke_all_user_sessions(user_id=user.id)
```

**Scenario 2: Password Reset**
When a user resets their password, you usually want to invalidate all old sessions, but keep the current session they just used to reset it alive!
```python
# The token they are currently using to make the API request
current_token = request.cookies.get(auth.config.cookies.name)

await auth.revoke_all_user_sessions(
    user_id=user.id, 
    except_token=current_token
)
```

## Account Management & Recovery

### `generate_password_reset_token(email: str) -> str`
Generates a secure, time-bound JWT for password resets. Also triggers the `send_password_reset` email hook if configured.
*   **Exceptions:** Raises `QulfException` or `UserAccountDeactivatedError`.

### `reset_password(token: str, new_password: str) -> User`
Verifies the reset token and updates the user's password. Automatically marks their email as verified if `auto_verify_email` is enabled in config.
*   **Exceptions:** Raises `QulfException` if the token is invalid/expired.

### `generate_email_verification_token(email: str) -> str`
Generates a secure JWT for email verification. Triggers the `send_verification` email hook if configured.

### `verify_email(token: str) -> User`
Verifies the token and sets the user's `email_verified_at` timestamp.

### `change_password(user_id: str, old_password: str, new_password: str) -> User`
Allows an authenticated user to change their password, verifying their current password first.
*   **Exceptions:** Raises `QulfException` if the `old_password` is incorrect.

### `delete_account(user_id: str) -> None`
Deletes the user account based on the globally configured `DeletionStrategy` (e.g., hard delete vs soft delete). Respects the `account_deletion.enabled` flag in config.

## Role-Based Access Control (RBAC)

These methods allow for querying or enforcing roles and permissions programmatically. They automatically cache the results on the `User` object so multiple calls during the same request lifecycle do not trigger multiple database queries.

### `has_role(user: User, role_name: str) -> bool`
Returns `True` if the user possesses the specified role, otherwise `False`.

### `has_permission(user: User, permission_name: str) -> bool`
Returns `True` if the user possesses the specified permission (granted via any of their roles), otherwise `False`.

### `require_role(user: User, role_name: str) -> None`
Enforces that a user has a specific role. Raises an `AuthorizationError` if they do not.

### `require_permission(user: User, permission_name: str) -> None`
Enforces that a user has a specific permission. Raises an `AuthorizationError` if they do not.

## Configuration Reference (`QulfConfig`)

`QulfConfig` is powered by `pydantic-settings` and automatically loads values from your `.env` file (using the `QULF_` prefix) or via explicit instantiation.

### Global Settings
*   `project_name` (str): Defaults to `"Qulf"`.
*   `base_url` (str): Defaults to `"http://localhost:8000"`.
*   `secret_key` (str): **Required**. Must be a cryptographically secure 32+ character string used to sign JWTs.

### `sessions: SessionConfig`
*   `expires_in_days` (int): Days until a session token expires. Defaults to `7`.
*   `update_age_days` (int): Frequency window in days for updating session last-seen timestamp. Defaults to `1`.
*   `strategy` (Literal["jwt", "database"]): The session tracking strategy. Defaults to `"database"`.

### `cookies: CookieConfig`
*   `name` (str): The cookie key name. Defaults to `"qulf_session"`.
*   `secure` (bool): If `True`, restricts the cookie to HTTPS only. Defaults to `False`.
*   `same_site` (Literal["lax", "none", "strict"]): Cookie SameSite policy. Defaults to `"lax"`.
*   `http_only` (bool): Restricts JavaScript access to the cookie. Defaults to `True`.

### `deletion: DeletionConfig`
Controls how database records are deleted.
*   `default` (DeletionStrategy): `"soft"` or `"hard"`. Defaults to `"soft"`.
*   `table_overrides` (dict): Overrides for specific tables. Defaults to `{"session": DeletionStrategy.HARD}`.
*   `get_strategy(table_name)` (method): Resolves the active `DeletionStrategy` for a given table name.

### `password_reset: PasswordResetConfig`
*   `token_expires_in` (timedelta): Reset link lifespan. Defaults to 15 minutes.
*   `auto_verify_email` (bool): If true, resetting a password automatically verifies the user's email. Defaults to `True`.

### `email_verification: EmailVerificationConfig`
*   `token_expires_in` (timedelta): Verification link lifespan. Defaults to 24 hours.
*   `require_for_sign_in` (bool): If true, blocks unverified emails from logging in. Defaults to `False`.

### `email_update: EmailUpdateConfig`
*   `require_verification` (bool): If true, changing an email address sends a verification link to the new address before updating it. Defaults to `True`.

### `account_deletion: AccountDeletionConfig`
*   `enabled` (bool): Defaults to `True`. If `False`, the `DELETE /account` route will throw an exception instead of deleting.

### `email_hooks: EmailHooks`
Instead of locking you into a specific email provider (like SendGrid or AWS SES), Qulf provides async hooks so you can write your own dispatch logic!
*   `send_password_reset` (Callable[[str, str], Awaitable[None]]): Async function taking `(email, token)`.
*   `send_verification` (Callable[[str, str], Awaitable[None]]): Async function taking `(email, token)`.

## Framework Integration Helpers

All framework modules (`qulf.frameworks.fastapi`, `qulf.frameworks.litestar`, `qulf.frameworks.flask`, `qulf.frameworks.django`) expose unified helper patterns:

### `serve_qulf(auth: Qulf)`
Mounts all core authentication endpoints (`/sign-up`, `/sign-in`, `/sign-out`, `/session`, etc.) and automatically attaches installed plugin routers under the same router namespace.

### `get_current_user(auth: Qulf)`
Dependency / helper function that extracts and validates the session cookie, returning the authenticated `User` object. Raises 401 Unauthorized if missing or invalid.

### `get_current_session(auth: Qulf)`
Dependency / helper function returning the active `Session` object.

### `RequiresRole(auth: Qulf, roles: str | list[str], mode: Literal["all", "any"] = "all")`
Route dependency or decorator verifying user role access:
*   `mode="all"`: User must possess **all** listed roles.
*   `mode="any"`: User must possess **at least one** of the listed roles.

### `RequiresPermission(auth: Qulf, permissions: str | list[str], mode: Literal["all", "any"] = "all")`
Route dependency or decorator verifying user permission access:
*   `mode="all"`: User must possess **all** listed permissions.
*   `mode="any"`: User must possess **at least one** of the listed permissions.

## Plugin Development & Lifecycle Hooks (`QulfPlugin`)

Custom plugins extend Qulf by inheriting from `QulfPlugin` (importable from `qulf.plugins`). Plugins can hook into authentication events, mount custom framework routes, and dynamically inject database columns into your ORM models.

```python
from qulf.plugins import QulfPlugin
from qulf.exceptions import ConfigurationError
from qulf.routing import QulfRoute, QulfRequest, QulfResponse
from qulf.types import Session, User, UserCreate
```

### Plugin State & `self.auth`

Every plugin class defines a unique `name: str` and has access to the parent `Qulf` engine via the `auth` property.

```python
class MyPlugin(QulfPlugin):
    name = "my_plugin"
```

#### `auth` Property & `ConfigurationError`

The `auth` property provides strict typing for IDE autocomplete and safeguards against uninitialized access:

```python
@property
def auth(self) -> "Qulf":
```

*   `self.auth` is set automatically when you register the plugin in `Qulf(plugins=[MyPlugin()])`.
*   If you attempt to access `self.auth` before `setup()` has been invoked by the engine, a `ConfigurationError` is raised:
    ```python
    ConfigurationError: Plugin `my_plugin` has not been initialized by Qulf.
    ```

---

### Hook Signatures & Reference

#### `setup(self, auth: Qulf) -> None`
Called synchronously during `Qulf.__init__()` when the engine is instantiated.

```python
def setup(self, auth: "Qulf") -> None:
```

*   **Parameters**:
    *   `auth`: The central `Qulf` engine instance.
*   **Behavior**: Assigns `self.auth = auth`. Override this if your plugin needs to validate configurations, subscribe to external event emitters, or initialize internal clients. Always call `super().setup(auth)` if overriding.

---

#### `get_custom_columns(self) -> dict[str, dict[str, type]]`
Defines generic custom database columns to inject into tables (e.g. `user`, `session`).

```python
def get_custom_columns(self) -> dict[str, dict[str, type]]:
```

*   **Returns**: A nested dictionary mapping `{table_name: {column_name: python_type}}`. Supported standard Python types include `str`, `int`, `bool`, and `datetime`.
*   **Behavior**: During engine boot, Qulf passes these fields to the active database adapter's schema injector (`SchemaAdapter.inject_custom_columns()`), which dynamically creates corresponding ORM fields:
    ```python
    def get_custom_columns(self) -> dict[str, dict[str, type]]:
        return {
            "user": {
                "two_factor_enabled": bool,
                "two_factor_secret": str,
            }
        }
    ```

---

#### `get_{orm}_columns(self) -> dict[str, dict[str, Any]]` (ORM-Specific Hook)
Optional hook pattern allowing plugins to define native ORM column constructs rather than generic Python types.

```python
def get_sqlalchemy_columns(self) -> dict[str, dict[str, Any]]: ...
def get_sqlmodel_columns(self) -> dict[str, dict[str, Any]]: ...
def get_django_columns(self) -> dict[str, dict[str, Any]]: ...
```

*   **Naming Convention**: The method name must match `get_{adapter_name}_columns`, where `{adapter_name}` corresponds to `auth.db.name` (e.g., `sqlalchemy`, `sqlmodel`, `django`).
*   **Precedence & Deep Merging**: If defined, Qulf calls this method and deep-merges its column definitions over any fields returned by `get_custom_columns()`. This provides an escape hatch to declare native attributes, such as indexes, foreign keys, column constraints, nullable flags, or custom column types:
    ```python
    def get_sqlalchemy_columns(self) -> dict[str, dict[str, Any]]:
        from sqlalchemy import Boolean, String, mapped_column

        return {
            "user": {
                "is_verified": mapped_column(Boolean, default=False, index=True),
                "verification_code": mapped_column(String(64), nullable=True),
            }
        }
    ```
*   **CLI Sync Support**: The `qulf sync` CLI command inspects both `get_custom_columns()` and `get_{orm}_columns()` via AST parsing to generate and update static model files automatically.

---

#### `get_routes(self) -> list[QulfRoute]`
Defines framework-agnostic HTTP endpoints mounted under the framework application router.

```python
def get_routes(self) -> list[QulfRoute]:
```

*   **Returns**: A list of `QulfRoute` definitions.
*   **Built-in RBAC**: Each `QulfRoute` accepts optional `require_roles` and `require_permissions` parameters, which framework integrations automatically enforce before the route handler is invoked:
    ```python
    def get_routes(self) -> list[QulfRoute]:
        async def verify_handler(request: QulfRequest) -> QulfResponse:
            return QulfResponse(status_code=200, body={"status": "verified"})

        return [
            QulfRoute(
                path="/verify-status",
                methods=["GET"],
                handler=verify_handler,
                require_roles=["user"],
            )
        ]
    ```

---

#### `async def before_user_create(self, user_data: UserCreate) -> UserCreate`
Asynchronous lifecycle hook executed during `sign_up()` **before** persisting the user record to the database.

```python
async def before_user_create(self, user_data: UserCreate) -> UserCreate:
```

*   **Parameters**:
    *   `user_data`: `UserCreate` instance containing registration fields (`email`, `password`, `name`, `username`, and extra plugin fields).
*   **Returns**: The (potentially mutated) `UserCreate` object passed along to subsequent plugins and the database adapter.
*   **Usage**: Validate fields (e.g. email domain whitelist), sanitize strings, normalize usernames, or reject unauthorized registrations by raising a `QulfException`.

---

#### `async def after_user_create(self, user: User) -> None`
Asynchronous lifecycle hook executed immediately **after** user registration has been successfully committed.

```python
async def after_user_create(self, user: User) -> None:
```

*   **Parameters**:
    *   `user`: The newly created `User` model instance returned from the database adapter.
*   **Usage**: Send verification emails, dispatch welcome webhooks, initialize customer IDs in third-party services (e.g. Stripe), or create initial profile entries.

---

#### `async def before_sign_in(self, email: str, ip_address: str | None = None) -> None`
Asynchronous lifecycle hook executed during `sign_in()` **before** credentials are authenticated.

```python
async def before_sign_in(self, email: str, ip_address: str | None = None) -> None:
```

*   **Parameters**:
    *   `email`: Email string entered by the user.
    *   `ip_address`: Optional client IP address passed to `auth.sign_in()`.
*   **Usage**: Check rate limits, evaluate IP geofencing/blacklists, or audit incoming sign-in attempts. Raising an exception aborts the login process before password hashing is evaluated.

---

#### `async def after_sign_in(self, user: User, session: Session) -> None`
Asynchronous lifecycle hook executed immediately **after** password verification succeeds and an active session is issued.

```python
async def after_sign_in(self, user: User, session: Session) -> None:
```

*   **Parameters**:
    *   `user`: The authenticated `User` record.
    *   `session`: The active `Session` record created for this authentication.
*   **Usage**: Enforce secondary authentication factors (such as TOTP 2FA by deleting the active session and raising `Requires2FAError`), log successful sign-in timestamps, or sync audit trails.

### Complete Plugin Implementation Example

```python title="app/plugins/security.py"
from datetime import datetime, timezone
from typing import Any
from qulf.exceptions import ConfigurationError, QulfException
from qulf.plugins.base import QulfPlugin
from qulf.routing import QulfRequest, QulfResponse, QulfRoute
from qulf.types import Session, User, UserCreate

class SecurityAuditPlugin(QulfPlugin):
    name = "security_audit"

    def setup(self, auth) -> None:
        super().setup(auth)
        # self.auth is now accessible without raising ConfigurationError

    def get_custom_columns(self) -> dict[str, dict[str, type]]:
        return {
            "user": {
                "failed_login_count": int,
                "last_security_check": datetime,
            }
        }

    def get_sqlalchemy_columns(self) -> dict[str, dict[str, Any]]:
        # Native SQLAlchemy definitions take precedence
        from sqlalchemy import DateTime, Integer, mapped_column

        return {
            "user": {
                "failed_login_count": mapped_column(Integer, default=0),
                "last_security_check": mapped_column(DateTime(timezone=True), nullable=True),
            }
        }

    def get_routes(self) -> list[QulfRoute]:
        async def security_status(request: QulfRequest) -> QulfResponse:
            return QulfResponse(status_code=200, body={"status": "healthy"})

        return [
            QulfRoute(
                path="/security/status",
                methods=["GET"],
                handler=security_status,
                require_roles=["admin"],
            )
        ]

    async def before_user_create(self, user_data: UserCreate) -> UserCreate:
        if user_data.email.endswith("@blocked-domain.com"):
            raise QulfException("Sign-up is not allowed for this domain.")
        return user_data

    async def after_user_create(self, user: User) -> None:
        print(f"Audit: New user created: {user.email}")

    async def before_sign_in(self, email: str, ip_address: str | None = None) -> None:
        print(f"Audit: Sign-in attempt for {email} from IP {ip_address}")

    async def after_sign_in(self, user: User, session: Session) -> None:
        print(f"Audit: User {user.id} signed in with session {session.token[:8]}...")
```
